## 验证限制与后续不足

- 未安装或启动本轮 APK 到设备；Android 7 真机兼容、Android Clang/WAMR 实际执行、SAF 慢速 provider、真实输入法及触控仍需设备验证。JVM 测试的编译器、WASM 执行和 Android 类是可控桩，不声称已验证真实 ARM64 执行。
- API 24/25 的强制结束使用 Android 旧进程实现中的 PID，再回退公开 destroy 方法；供应商定制实现需要真机确认。新版设备使用公开强制结束 API。
- lint 保留平台属性、固定横屏、JavaScript 启用、已有 SDK 检查、空间估计、闲置资源和启动图标配置等非阻断警告，没有关闭检查。
- Python 代码以应用身份运行，可访问应用私有文件和网络；C/C++ 仍采用 WASI。此次接口认证阻止其他普通应用直接提交代码，不把 Python 子进程变成沙箱。
- 编译缓存仍以整个请求复用对象，尚未实现按单个源文件/头文件依赖的增量构建；前端仍是大型单文件，模块化应单独规划。
- targetSdk 28、真实调试器、CMake、应用内 Git、C/C++ 实时交互和 Python 生成文件导出保持现状，不作为本次 bug 修复已完成的功能。
- 构建产物为本地 debug APK，未改版本号、未发布正式签名版本；不覆盖 `release/` 历史产物。
