# 程序运行终端首版实现与验证

日期：2026-10-05（Asia/Shanghai）
基线：`c996849`，分支 `local-runtime`
状态：实现、主机回归及 debug APK 完成；用户已确认真机调试延后，设备验收未完成。

## 使用

1. 安装新的 debug APK；已导入的 C/C++ 和 Python 资源包继续使用。
2. 打开项目，普通“运行”或 Ctrl+Enter 自动进入“终端”。在底部输入行输入，Enter
   发送，输出与已发送内容连续显示在同一终端面板；无需切换 stdin/stdout。
3. Shift+Enter 在输入中换行，多行粘贴提交完整行并保留最后的未提交行。中文组字
   期间 Enter 不提交程序输入。异步输出不修改正在编辑的草稿。
4. Ctrl+C 或停止按钮停止程序；输入行为空时 Ctrl+D/EOF 关闭标准输入，继续接收
   输出尾部。复制和清屏不停止程序。
5. 原有 stdin 留作测试数据，运行菜单选择“使用测试输入运行”，发送后自动 EOF。
6. 交互运行默认 600000 ms，可在设置里调整到 1000–3600000 ms；构建单独 30 秒。

终端显示使用 xterm.js 5.5.0 和 addon-fit 0.10.0。本地资产记录下载来源及 SHA-512
完整性值，并包含许可证；运行无需联网。沿用既有字体、主题、尺寸和软键盘面板布局。

## 主要实现

- `RunSession`：每次任务拥有 UUID、输入队列、幂等输入序号和有序事件缓冲。单次输入
  最多 64 KiB，队列 256 KiB；重复序号/相同内容只投递一次，内容冲突和旧会话拒绝。
  已接受输入的指纹最多保留 64 个，避免为去重无限持有输入全文。
- 标准输入通过专用线程写入；HTTP 只确认入队，不等待程序读取。EOF 按队列顺序执行；
  程序不读取时，输入容量满返回明确错误。取消结束执行并释放阻塞写入。
- 输出事件保留 2 MiB、最多 4096 帧，淘汰旧帧时返回 gap。每次响应约 64 KiB，继续
  提供最新输出。终端最多 5000 行滚动历史，输出仅作为终端数据处理；禁用 OSC 52/8。
- `/api/v1/tasks/{id}/events` 输出按序重放；`/input` 和 `/eof` 带 session_id/seq。
  保留原会话令牌认证，API 兼容原任务和批处理输出接口。
- Python 输入从全局 stdin 迁移到会话；输出总量超过旧结果上限仍继续推送终端事件。
- WASI 输入保持开放、独立 JNI 写入/关闭方法；运行线程持有的类监视器不阻塞输入
  控制。读取线程实时回调 Java，并按流增量解码 UTF-8。
- WASI 取消/超时先关闭写端，让等待 fd_read 的程序看到 EOF，再终止模块。所有句柄
  检查运行 ID；线程创建失败不继续执行 guest；非零退出码不计为 success。
- 交互构建包裹当前 crt1 实际调用的 `__main_void`，在用户代码前配置 guest stdout /
  stderr 无缓冲。普通 main 包裹不足以覆盖该 WASI 入口。模式参数纳入现有缓存键。
- 前端会话客户端按事件序号避免重复输出，使用最终退出事件排空尾部。确认丢失时重试
  相同输入序号；前端失联或停止长期未确认时退出等待并显示错误。

设备恢复连接后安装 `android/app/build/outputs/apk/debug/app-debug.apk`，用项目目录中的
`test/terminal-projects/` 四组样例依次验证：

1. Python：无换行中文提示、两次 input()、中文/emoji、EOF 后输出完整。
2. C：两个 scanf、提示不用补 fflush、多次输入、EOF。
3. C++：cout/cin/getline 的提示刷新、UTF-8 和 EOF。
4. cancel：输入 1 后等待 scanf 时停止；输入 2 后 CPU 死循环时停止；停止后立即运行
   新项目，确认无残留输入或线程。重复 30 次并观察内存、FD 和应用响应。
5. 平板输入法：组字确认、Enter、粘贴、软键盘弹出/收起、终端滚动、切后台再恢复。

WAMR 阻塞调用唤醒能力取决于已有 libiwasm 的构建。当前实现以关闭写端唤醒读取后终止；
仍须在真机验证。若无法可靠停止，按原规划改为可取消的宿主 I/O 或独立执行进程。

首版按行运行；shell、REPL、PTY/raw、隐藏密码输入和 C++ 用户自行关闭缓冲/流绑定的
复杂交互不作为本轮已验证能力。程序仍使用临时工作目录，生成文件不导出；Python
仍以应用身份运行，WASI 文件访问边界保持原状。前台输出 P95 延迟尚未在真机测量。
