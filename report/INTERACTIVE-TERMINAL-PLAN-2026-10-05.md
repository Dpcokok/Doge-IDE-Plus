# Doge IDE+ 程序运行终端规划

日期：2026-10-05（Asia/Shanghai）
基线：`c996849`，`local-runtime` 分支
状态：首版方向已由用户确认；本文规划，尚未实施。

用户确认的优先级：运行程序时直接在输出窗口输入，提示、输入和结果连续显示；同时服务 Python 和 C/C++。

## 1. 首版体验与范围

点击“运行”后自动展开“终端”面板，显示构建状态和程序输出。用户点终端即可输入，Enter
发送一行，程序结果继续接在同一窗口里。输入时支持中文组字、退格、左右移动、选中复制
和粘贴。面板提供“停止”“发送 EOF”“清屏”“复制记录”，触摸工具栏提供 Enter、Ctrl+C、
Ctrl+D，外接键盘使用对应快捷键。

示例：

```text
正在运行 main.py
你的名字：小明
Hello, 小明!

[程序结束，退出码 0]
```

终端自动跟随新输出；用户向上翻看时保留当前位置，提供回到底部按钮。程序结束后记录
保留，输入禁用。再次运行创建新的运行 ID 和缓冲，不把输入发送到上一次任务。

默认“交互运行”。原来的预填输入用于“测试输入”运行方式，保留给算法题、批量数据和
自动测试；交互运行不自动发送上次输入框的残留内容。

首版采用程序运行终端、按行提交输入。shell、常驻 Python `>>>`、多终端并行、逐键 raw
模式、密码输入隐藏、全屏 TUI/游戏属于后续能力。前端显示 ANSI 不等于后端获得完整
TTY 能力，首版须准确标注支持范围。

## 2. 已核实的现状

|---|---|---|

## 3. 推荐实现

### 3.1 终端显示与执行模式

前端采用本地打包的 `@xterm/xterm` 与 `@xterm/addon-fit`，固定依赖版本、保留许可证，
随 APK assets 发布，运行时无需 CDN。首版优先使用默认渲染，不先增加 WebGL 等插件。

将新增逻辑放进 `web/terminal/`：

- `terminal-view.js`：显示、行编辑、组字、焦点、键盘/触控操作。
- `terminal-session.js`：请求、输出游标、重连、输入确认和会话状态。
- `terminal.css`：尺寸、主题、移动输入工具栏。

`doge-ide.html` 负责挂载和命令入口，避免把新增会话代码全部写回已有大脚本。
终端库本身不提供 pipe 模式的行编辑，必须明确实现输入缓冲；异步输出到来时，当前
输入内容、光标和输入法组字不能丢失或重复提交。

Python 和 C/C++ 首版沿用管道，前端承担按行输入与回显。Python 保持 stdout/stderr
恢复到原始 FD；原始错误文本仍用于问题定位。C/C++ 新增实时输出和持续输入，不改变
WASI 的目录访问边界。

### 3.2 C/C++ 提示刷新

`printf("请输入："); scanf(...)` 的 stdout 连接 pipe 时可能使用全缓冲，即使读取线程
实时传输也看不到提示。必须先在真机验证：

1. 交互模式链接一个 WASI 启动辅助对象，在用户 `main` 前为 guest stdout 设置刷新策略，
   推荐首版无缓冲；C++ 同时覆盖 `std::cout` 与关闭 stdio 同步的情况，明确需要 flush 的边界。
2. 辅助对象、交互/批处理模式均纳入缓存键，防止两种运行方式复用不匹配的对象。
3. 策略只作用于交互执行。大量输出仍须按后端批次聚合，测量无缓冲带来的性能成本。

宿主 App 的 `setvbuf` 不能代替修改 WASM guest 的 stdio。启动辅助对象和库行为均须
用当前资源包里的 WASI libc/libc++ 核实，未经验证不得宣称任意 C++ 输出都会立即刷新。

### 3.3 运行会话与输入所有权

任务继续负责排队、构建和最终结果；新增 `RunSession` 管理一次运行的输入、输出和终止。
首版同一时刻只运行一个程序，保留当前串行调度，后续常驻解释器/多终端再分离长期会话
与构建调度。

```text
TerminalView ↔ TerminalSessionClient ↔ 已鉴权的本地 API
                                      ↕
                         TaskRegistry / RunSession
                              ↙              ↘
                     Python 管道          WASI/JNI 管道
```

`RunSession` 持有：唯一 ID、项目快照、状态、输入序号、输出序号、运行句柄、容量限制和
退出信息。运行器提供“写输入 / 关闭输入 / 停止 / 输出通知”能力。移除终端输入对全局
`activeStdin` 的依赖，原子校验会话 ID 和输入句柄归属。

状态流：`queued → compiling → linking → running → finished`；Python 跳过不需要的
构建阶段。`inputReady` 为独立能力标志，不凭借提示文本猜测程序是否正在等待输入。

EOF 是半关闭：先送完此前已接受的输入，再关闭写端，输出继续读取到结束。重复 EOF
无副作用，EOF 后追加输入明确拒绝。停止和 EOF 分开处理。

JNI 控制方法以运行句柄为参数，短时间持锁；不能等待正在持类锁执行的 `nativeRun`。
native 读写线程释放句柄前禁止复用，处理 FD 编号重复分配的情况。

### 3.4 输入和输出接口草案

复用已鉴权的 `/api/v1/tasks`，追加运行模式和交互参数：

```json
{
  "language": "python",
  "entry": "main.py",
  "files": [],
  "run_mode": "interactive",
  "compile_timeout_ms": 30000,
  "run_timeout_ms": 600000
}
```

| 接口 | 语义 |
|---|---|
| `POST /api/v1/tasks` | 创建任务，返回 task ID、运行会话 ID 和能力 |
| `GET /api/v1/tasks/{id}/events?after=N` | 获取有序的新输出/状态事件与下一游标；不重复携带全部日志 |
| `POST /api/v1/tasks/{id}/input` | 提交带单调序号的输入，返回已接受序号 |
| `POST /api/v1/tasks/{id}/eof` | 在先前输入之后关闭写端，幂等 |
| `POST /api/v1/tasks/{id}/cancel` | 停止当前运行；保留现有任务接口兼容 |

输入以 UTF-8 字节计算队列容量，由独立写线程处理，HTTP 线程仅确认入队。队列满时返回
明确错误；程序不读取输入不能阻塞服务工作线程。网络请求结果不明确时，以会话 ID +
输入序号查询/重试，后端去重，不能盲目再次发送同一行。

输出事件包含 `seq`、`kind`、`stream`、内容和状态。两条输出管道在同一序列分配点
汇合，保持后端实际观测的顺序；不能从当前两个独立大字符串恢复精确的 stdout/stderr
原始写入时序。UTF-8 在每条读取流上增量解码，ANSI 序列交由终端库连续解析。

终端视觉流合并显示，诊断原文单独采集。输入回显由明确的一层负责，并与“正在编辑的
本地输入行”区分，重新拉取事件不重复回显。最终状态只能在最后一段输出提交后发出，
客户端按输出事件序列结束，避免状态先到导致尾部输出丢失。

首版使用紧凑轮询，活跃时目标间隔 50–100 ms，空闲时适当放慢，单次返回限制批次大小。
输入控件本地即时响应；前台低负载时目标是提示/输出传输端到端 P95 小于 200 ms，并以
真机测量为准。后续若需 SSE/fetch 流，先拆出专用连接执行器；原生 EventSource 和
浏览器 WebSocket 不能直接复用当前自定义认证头策略，令牌不放入 URL。

### 3.5 输出上限、时限和生命周期

建议初始默认值：单次输入最多 64 KiB、待写队列 256 KiB、输出事件保留 2 MiB、前端
滚动历史约 5000 行。所有值需压力测试后调整。容量满时淘汰旧事件，继续接收最新输出，
返回丢失区间并提示，不能沿用“达到总上限后永久停止显示新输出”的行为。ANSI 状态
因丢失区间不完整时重置解析/显示状态，明确提示，不悄悄拼接残片。

交互运行采用独立时限，建议默认 10 分钟可配置；构建默认 30 秒，批处理保留现有短时限。
交互时限从运行开始计算，排队和编译不消耗等待用户输入的时间。不以“没有输出”自动
判定正在等输入，也不未经实现就声称能暂停纯计算的计时。停止按钮始终可用。

终端关闭/清屏只影响显示，停止是单独动作。切后台时原生运行按既定时限继续，恢复前台
拉取游标后事件；进程被系统回收后显示“会话已结束”，不把旧输入自动重放给新进程。
第一版不新增常驻后台服务。

保留会话令牌认证及 WebView 确切来源限制。程序输出作为终端数据，不作为 HTML。
禁止输出自动操作系统剪贴板（如 OSC 52），链接由用户触发且经已有来源策略处理。

## 4. 分阶段实施与验收

| 阶段 | 工作 | 退出条件 |
|---|---|---|
| P0 原生验证 | 真实 App 身份验证 Python pipe、WASI 提示刷新/持续 stdin/输出/EOF/取消；WebView 验证终端库中文 IME | 两种语言的无换行提示可见；等输入/死循环均可停止；阻塞输入取消不冻结 App |
| P1 会话与接口 | RunSession、按 ID 输入队列、去重序号、有序事件、容量/时限 | HTTP/JVM 回归覆盖输入不串任务、重试不重复、EOF 顺序和输出游标 |
| P2 Python 终端 | 本地终端资产、同窗口行输入、触控/IME、Python 运行、复制与滚动 | 连续多次 input() 正常；中文输入只发送一次；后台输出不破坏输入行 |
| P3 C/C++ 接入 | JNI 实时输出、输入写端生命周期、guest 刷新策略、取消唤醒 | printf+scanf、cout+cin、循环输入、EOF 和停止真实 WASM 用例全部通过 |
| P4 联合验收 | 默认交互入口、测试输入模式、软键盘布局、重连/大输出、旧测试/完整构建 | 两种语言体验一致；现有回归、APK/lint、平板真机验收全部通过 |

P0 必须在真实 App 进程域里验证；`run-as` 或 Windows 子进程测试不能证明 WAMR
阻塞系统调用的取消可用。当前 WAMR 头文件明确说明：缺少阻塞唤醒支持时，终止调用
可能不能及时唤醒宿主阻塞操作。

如果关闭 stdin 写端并请求终止仍不能可靠释放 WASI 读取，P3 需要调整为可取消的宿主
I/O，或将 WAMR 移到独立执行子进程；以 P0 结果决定，不能仅延长超时掩盖问题。

## 5. 关键验收用例

- Python 无换行提示 + 连续三个 input()；输入中文、emoji，空行和超长行。
- C `printf("请输入：") + scanf`；C++ `cout << "请输入：" + cin`；源文件无需用户补 fflush。
- 程序等待输入时 Ctrl+C/停止；程序死循环时停止；EOF 后输出全部排空。
- Enter 与组字确认、退格、左右移动、复制、Ctrl+L/清屏；多行粘贴保留行序，尾部未提交行保持可编辑。
- 程序在输入行编辑过程中继续输出，组字和光标不乱；ANSI 颜色、回车覆盖的进度显示。
- 大输出持续产生数分钟，达到历史上限后仍看到最新内容，内存保持有限。
- 输入序号重复、网络超时后重试、旧会话输入抵达新运行、EOF 与输入/停止并发。
- 前台/后台恢复、面板隐藏再打开、软键盘出现/收起、程序结束后保留退出码和日志。
- 原有保存/编译/补全/鉴权/代理/批处理回归不受影响，Android API 24 兼容路径可用。

按阶段划分独立提交，每个原生改动先做对应回归再提交。首版完成以前不承诺 PTY/raw
能力；后续 Python REPL/PTY 可使用相同 RunSession 和终端 UI，但需另外验证进程组
信号、resize、回显归属和 stdout/stderr 合并语义。NDK 的 openpty/forkpty 从 API 23
可用，仍需确认设备 SELinux、启动方式以及 Android 多线程进程 fork 后的安全执行路径。
