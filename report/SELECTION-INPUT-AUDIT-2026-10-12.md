# 选区删除后的输入恢复与项目检查

完成日期：2026-10-12（Asia/Shanghai）。

后续反馈：用户确认 1.1.5 上选择多个字符后按 Backspace 仍无法输入。下列浏览器检查没有证明搜狗真机故障已经解决。后续新增的原生输入连接同步与诊断见 `NATIVE-INPUT-CONNECTION-2026-10-12.md`。

用户环境：Android 平板、外接键盘、搜狗输入法；最新版测试 APK；鼠标拖选多字后删除。尚未连接真机，以下复现使用实际 Edge/CodeMirror、CDP 鼠标和输入法事件，以及缺失事件的重放。

## 已复现并修复

| 条件 | 修复前结果 | 本轮处理 |
|---|---|---|
| 鼠标拖选、多字删除后，输入法只发送带 isComposing 标记的 input，遗漏 compositionstart/update/beforeinput | textarea 收到 xy，文档仍为 af；编辑器保持焦点、非只读 | input 捕获阶段也接续组字，通过 CodeMirror 自身的开始事件建立范围 |
| 组字结束，候选原生选区仍存在 | 下一次 z 替换掉已提交的 xy，文档成为 azf | 仅在 textarea 内容与已读基线一致、文档无选区时收起已提交候选选区；复制产生的镜像选区保留 |
| 已提交的 insertText 保留原生选区，文档也存在用户选区 | 文字无法替换文档选区 | 提交事件解除原生读取阻断，不改变用户实际替换范围 |
| 原生上下文菜单结束后用户已改变选区或删除 | 旧选区标记阻止恢复，旧定时器可能晚到并重置输入 | 选区离开菜单范围时结束菜单桥接并清理旧检测定时器 |
| Tab keyup 的旧异步恢复在新选区或新文档上执行 | 后建立的 bcde 或另一文件的 other 选区被清空 | 删除过时的强制折叠逻辑，保留多行缩进选区 |
| 输入法用非组字 insertText 提交，却遗漏 compositionend | Tab 一直等待组字结束，补全不接受 | 已提交的输入通过 CodeMirror 自身结束事件完成旧组字 |
| 组字结束后的延迟 Tab 接受遇到新补全会话或位置变化 | 存在接受后来的候选、对新前缀执行旧动作的窗口 | 核对补全会话、文档、前缀和光标位置 |
| 触摸候选收到 pointerdown/up，但浏览器不发兼容 click | 点选保持 pr，没有插入 printf | 未滑动的触摸松开直接接受；滑动、取消、文件或候选变化时放弃；不重复处理兼容 click |

Android 壳还存在返回键隐藏键盘前调用 clearFocus() 的风险：它会清除 WebView 焦点，使后续硬件键盘输入无法交给网页。已移除该调用，保留隐藏键盘和双击返回退出。该原生路径通过编译和 lint，未在设备上复现，仍需真机验收。

正常组字保留候选选区；只读、禁用输入、剪贴板镜像和多个光标保留原生行为。没有重建编辑器或清空用户代码。

## 检查范围

- 编辑器选区、删除、输入法、焦点、快捷键、补全、配对和延迟处理入口；Android WebView 生命周期、返回键与缓存配置。
- 只读状态由文件可用性控制，运行和保存没有额外锁定当前编辑器。
- 项目草稿和保存、文件切换、本地服务、clangd、运行进程和终端输入的相关实现及现有行为回归。
- 未覆盖所有大文件、输入法和 Android WebView 版本；不能排除其他设备事件序列。

## 预防

把每次选区、删除或补全操作后仍能继续输入作为回归检查的不变量，覆盖缺失事件、不同提交顺序、拖选和异步操作失效。缺失事件恢复包括 input，避免只处理 compositionupdate/beforeinput 后遗漏更短的设备序列。
